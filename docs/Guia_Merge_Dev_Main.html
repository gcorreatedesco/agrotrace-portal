Cómo fusionar branches sin mezclar credenciales de entorno · AgroTrace 2026

Contexto del problema

AgroTrace tiene dos entornos separados, cada uno con su propio proyecto Supabase:

BranchProyecto SupabaseUso
mainPROD — jqkyifuyaxxwugrnjfnqUsuarios reales
devDEV — aitodoqcsawntgznwtvjPruebas y desarrollo

Las credenciales de conexión (URL + clave anon) están hardcodeadas en 4 archivos HTML:

  • index.html
  • agrotrace_prototipo_v3.html
  • portal_rt.html
  • portal_superadmin.html
El riesgo Un git merge directo entre branches mezcla el contenido de los archivos y las credenciales del entorno equivocado pisan las correctas. Por ejemplo: mergear dev en main sin cuidado dejaría la URL de DEV en producción — los usuarios reales se conectarían a la base de datos de pruebas.

Solución: script ci/merge.py

El script realiza el merge y corrige las credenciales automáticamente. Lo que hace internamente:

  1. 1
    Cambia al branch destino
  2. 2
    Guarda las credenciales del destino leyendo los archivos desde git, sin tocar el disco
  3. 3
    Ejecuta git merge --no-commit --no-ff desde el branch origen
  4. 4
    Restaura las credenciales guardadas, pisando cualquier URL incorrecta que haya traído el merge
  5. 5
    Commitea y pushea

Por qué se agregó el check al CI

El CI (GitHub Actions) corre ci/sanity_check.py en cada push a cualquier branch. Se le agregó la función check_supabase_credentials() como segunda línea de defensa:

BranchQué verificaSi falla
mainTodos los HTML tienen URL de PRODEmail de alerta + push bloqueado
devTodos los HTML tienen URL de DEVEmail de alerta + push bloqueado
Relación script / CI El script previene el error. El CI lo detecta si de todas formas ocurre (por ejemplo, si alguien hace un merge manual sin usar el script).

Cómo ejecutar un merge correctamente

Deploy: pasar cambios de dev a producción

# Desde cualquier branch, en la terminal del proyecto:
python ci/merge.py main

El script cambia a main, mergea dev, restaura credenciales de PROD y pushea.

Mensaje de commit generado: deploy: merge dev -> main [credenciales MAIN restauradas]

Sync: traer cambios de main a dev

Útil cuando se hacen cambios directamente en main (ej: README, documentación) que deben reflejarse en dev.

python ci/merge.py dev

El script cambia a dev, mergea main, restaura credenciales de DEV y pushea.

Mensaje de commit generado: sync: merge main -> dev [credenciales DEV restauradas]

Qué hacer si hay conflictos

El script distingue dos tipos:

Conflictos en los 4 HTML de credenciales

Los resuelve automáticamente. El script reemplaza todo el contenido de URLs por las correctas, eliminando los marcadores de conflicto.

Conflictos en archivos de código

El script aborta y muestra qué archivos tienen conflictos. Hay que resolverlos manualmente antes de volver a intentar el merge. 
# 1. Abrir el archivo con conflicto en VS Code y resolver
#    (buscar marcadores <<<<<<< / ======= / >>>>>>>)

# 2. Marcar como resuelto y completar el merge
git add <archivo-resuelto>
git commit

# 3. Corregir credenciales manualmente en los 4 HTML
#    PROD: jqkyifuyaxxwugrnjfnq.supabase.co
#    DEV:  aitodoqcsawntgznwtvj.supabase.co
git add index.html agrotrace_prototipo_v3.html portal_rt.html portal_superadmin.html
git commit --amend --no-edit
git push origin <branch>
Nunca usar git merge directo entre dev y main.
Siempre usar python ci/merge.py

Solución definitiva (migración a React + Vite)

Al migrar a React + Vite, las credenciales se moverán a un archivo .env que no entra en git (.gitignore). Cada entorno tendrá su propio .env local y el problema desaparece por completo — los merges nunca tocarán credenciales.

# .env.production
VITE_SUPABASE_URL=https://jqkyifuyaxxwugrnjfnq.supabase.co
VITE_SUPABASE_KEY=eyJ...

# .env.development
VITE_SUPABASE_URL=https://aitodoqcsawntgznwtvj.supabase.co
VITE_SUPABASE_KEY=sb_publishable_...
