Dominio y hosting: conceptos base

Para tener AgroTrace en una dirección www.agrotrace.com.ar necesitás dos cosas separadas que se contratan por separado y luego se conectan.

Buena noticia Tu app es HTML estático (no tiene código de servidor). Eso hace que el hosting pueda ser completamente gratuito.

Opciones de hosting gratuito

GitHub Pages (ya lo tenés)

Tu app ya corre en https://gcorreatedesco.github.io/agrotrace-portal/. Es gratuito, tiene HTTPS, y se actualiza solo con cada git push.

Limitación: el repo tiene que ser público para que GitHub Pages funcione gratis.

Cloudflare Pages (recomendado)

  • Gratis para siempre en el plan gratuito
  • Acepta repos privados (GitHub Pages gratuito no)
  • Deploy automático en cada git push
  • CDN global (carga más rápido desde cualquier lugar)
  • HTTPS automático incluido
  • Cada branch recibe su propia URL de preview automáticamente

Cómo migrar a Cloudflare Pages (15 minutos)

  1. Crear cuenta gratuita en cloudflare.com
  2. Workers & Pages → Create → Pages → Connect to Git
  3. Elegir repo agrotrace-portal
  4. Framework preset: None — Build command: vacío — Output: vacío
  5. Deploy → quedás en agrotrace-portal.pages.dev

Opciones de dominio propio

Opción A: .com.ar — NIC Argentina

  • Costo: ~$2.000–3.500 ARS/año (precio en pesos)
  • Requisito: CUIT o CUIL argentino
  • Registro: nic.ar — el ente oficial argentino
  • Ejemplo: agrotrace.com.ar

Opción B: .com — Cloudflare Registrar

  • Costo: ~US$10/año (precio de costo, sin markup)
  • Sin requisito de CUIT
  • Ventaja: si usás Cloudflare Pages, todo queda en un solo panel
  • Ejemplo: agrotrace.com

Ruta recomendada paso a paso

GitHub (tu código) ↓ push automático Cloudflare Pages (hosting gratuito) ↓ sirve los archivos DNS de Cloudflare (gratuito) ↓ apunta agrotrace.com.ar (dominio ~$3.000 ARS/año)

Paso 1 — Registrar el dominio en NIC Argentina

  1. Crear cuenta en nic.ar con tu CUIT
  2. Buscar agrotrace.com.ar y comprarlo (~$3.000 ARS/año)
  3. En la configuración DNS del dominio, cambiar los nameservers por los de Cloudflare (Cloudflare te da los valores exactos)

Paso 2 — Conectar el dominio a Cloudflare

  1. Crear cuenta gratuita en cloudflare.com
  2. "Add a site" → ingresar tu dominio
  3. Cloudflare te da 2 nameservers (ej: alice.ns.cloudflare.com)
  4. Cargar esos nameservers en NIC Argentina
  5. Esperar 1–24 hs a que se propague

Paso 3 — Crear el hosting en Cloudflare Pages

  1. En Cloudflare → "Pages" → "Create a project"
  2. Conectar tu cuenta de GitHub y elegir el repo
  3. Build settings: output vacío, sin build command
  4. Deploy

Paso 4 — Conectar dominio al hosting

  1. En Cloudflare Pages → "Custom domains"
  2. Ingresar www.agrotrace.com.ar
  3. Cloudflare configura el DNS automáticamente
  4. HTTPS activo en minutos

Seguridad del código en GitHub público

Concepto clave: el código del navegador siempre es visible

Cuando alguien abre tu app en el navegador y presiona F12 → Sources, ve exactamente el mismo código que está en GitHub. Hacer el repo privado no cambia esto.

Esto es una característica inherente de la web: todo HTML/CSS/JS que corre en el navegador es, por definición, visible para el usuario.

Riesgos reales evaluados

RiesgoNivelEstado actual
Alguien lee el código HTML/JSBajoSiempre visible por F12 igual

service_role_key expuestaCrítico✅ No está en el código HTML
Password de admin en git historyAlto⚠️ Pendiente cambiarla en Supabase
XSS (inyección de código por usuario)Alto✅ Corregido (función esc())
RLS mal configuradoCrítico✅ Implementado 3 niveles
Alguien copia la idea de negocioMedioRepo privado ayuda
🔴 Acción urgente pendiente Cambiar la contraseña de admin@agrotrace.dev en Supabase Dashboard → Authentication → Users. La contraseña anterior (AgroTrace2025!) quedó grabada en el historial de git y es visible para cualquiera que acceda al repo.

Cómo proteger el código fuente (repo privado)

Qué protege hacer el repo privado

  • ✅ Nadie puede navegar tu código en github.com
  • ✅ Competidores no ven tu lógica de negocio
  • ✅ Comentarios internos, TODOs, datos de prueba quedan ocultos

Qué NO protege

  • ❌ El código que corre en el navegador (F12 siempre lo muestra)
  • ❌ La anon key de Supabase (visible en el navegador)

Pasos para hacer el repo privado

  1. GitHub → tu repo → Settings → scroll hasta abajo → Change repository visibility → Make private
  2. GitHub Pages deja de funcionar (requiere plan pago para repos privados)
  3. Migrar a Cloudflare Pages (gratis, acepta repos privados) — ver Sección 2

Obfuscación: hacer el código ilegible

Además de ocultar el repo, podés transformar el código en algo técnicamente funcional pero prácticamente imposible de leer para un humano. Se llama ofuscación.

Antes (legible)Después (ofuscado)
function rLC(l){ const etapa = l.et; } function a1b(x){var _0x3f=x['et'];}

Un competidor casual abandona. Un hacker dedicado puede revertirlo, pero le lleva horas. Conviene agregar esto cuando el sistema esté en producción real — no antes.

Estrategia de branches para desarrollo sin afectar producción

main ──────────────────────── producción (lo que usan las ONGs) │ └── dev ──────────── donde probás cambios │ └── feature/X ── una mejora específica

Cuando terminás de probar en dev y todo funciona, hacés un merge a main y la producción se actualiza sola.

Con Cloudflare Pages: preview automático por branch

BranchURL generada automáticamente
mainagrotrace-portal.pages.dev (producción)
devdev.agrotrace-portal.pages.dev (preview)

No necesitás configurar nada extra. Cloudflare genera la URL de preview sola en cada push a cualquier branch que no sea main.

Flujo de trabajo

  1. Crear branch dev en GitHub
  2. Hacer cambios en el código (en dev)
  3. Probar en la URL de preview de Cloudflare
  4. Cuando funciona → merge a main
  5. Producción se actualiza sola en minutos
  6. Las ONGs nunca vieron nada raro

Supabase dev vs producción

No son lo mismo que las branches de GitHub

CosaQué controlaAnalogía
Branch de GitHubEl código (HTML/JS/CSS)La receta escrita
Proyecto de SupabaseLa base de datos (tablas, datos)La cocina real

Podés tener dos versiones del código (branches) pero si ambas apuntan a la misma base de datos, los cambios en la estructura de la base de datos afectan a las dos.

Qué pasa si compartís el mismo Supabase entre branches

Tipo de cambio en dev¿Afecta producción?
Cambio visual (CSS, layout)✅ No afecta
Nueva función JS✅ No afecta
Agregar una columna a una tabla⚠️ Sí — aparece en producción
Cambiar una política RLS⚠️ Sí — afecta a ONGs reales
Insertar datos de prueba⚠️ Sí — mezclados con datos reales

La solución: dos proyectos Supabase

main branch → Supabase PRODUCCIÓN (datos reales de ONGs) dev branch → Supabase DEV (datos de prueba, podés borrar todo)

Cómo crear el Supabase dev (sin nueva cuenta, sin pagar)

Supabase permite 2 proyectos gratuitos por cuenta. No necesitás otra cuenta.

  1. Entrar a supabase.com con tu cuenta actual
  2. Click en "New project", nombre: agrotrace-dev
  3. Abrir el SQL Editor del proyecto nuevo y ejecutar el contenido de supabase_schema.sql
  4. En la branch dev del HTML, cambiar las dos líneas de conexión:
// En dev branch
const SUPABASE_URL  = 'https://NUEVO-ID.supabase.co';
const SUPABASE_ANON = 'nueva-anon-key-del-proyecto-dev';

// En main branch — sin tocar
const SUPABASE_URL  = 'https://jqkyifuyaxxwugrnjfnq.supabase.co';
const SUPABASE_ANON = 'la-key-actual';
¿Cuándo necesitás el Supabase dev? Solo si vas a tocar la base de datos (nuevas tablas, columnas, cambios de RLS). Si tus próximos cambios son solo HTML/JS, podés seguir con el mismo Supabase sin riesgo.

Política de inactividad de Supabase (pausa automática)

Qué pasa exactamente

Supabase en el plan gratuito monitorea si tu proyecto recibe consultas reales a la base de datos. Si no recibe ninguna durante 7 días seguidos, lo pausa automáticamente.

EstadoConsecuencia
Proyecto activoTodo funciona normalmente
Proyecto pausadoLa app da error, los usuarios no pueden entrar
Datos cuando está pausado✅ Se conservan, no se borran
Para reactivarDashboard → "Restore project" → 1-2 minutos

Qué cuenta como "actividad"

Acción¿Evita la pausa?
Alguien inicia sesión en la app✅ Sí
Una ONG carga o consulta datos✅ Sí
Alguien abre el dashboard (aunque no cargue nada)✅ Sí — la app hace consultas automáticas al cargar
Vos entrás al dashboard de Supabase❌ No
El repo de GitHub existe❌ No
⚠️ Importante: también afecta al proyecto de producción Si ninguna ONG ni vos entrás a la app por 7 días, el proyecto de producción también se pausa. Durante la etapa de desarrollo esto es un riesgo real.

Keep Alive: qué es y cómo funciona

La analogía del sereno

Supabase es como un depósito prestado gratis con la condición: "si no veo actividad en 7 días, cierro". El keep alive es un sereno automático que pasa cada 5 días, toca el timbre, y se va. El dueño ve actividad y no cierra.

Qué es GitHub Actions

GitHub tiene un sistema para ejecutar tareas automáticas en horarios programados, como un despertador que en vez de sonar, ejecuta una acción.

Cada 5 días a las 8am: → GitHub despierta automáticamente → Hace una consulta mínima a Supabase (equivale a "entrar a la app y ver el dashboard") → Supabase registra actividad → El contador de 7 días se resetea → GitHub se vuelve a dormir

Todo esto pasa sin que vos hagas nada. Se configura una vez y funciona solo para siempre, gratis.

Cómo se implementa

Es un archivo de texto de 15 líneas que se agrega al repo en esta ubicación:

agrotrace-portal/ .github/ workflows/ keep-alive.yml
name: Keep Supabase alive
on:
  schedule:
    - cron: '0 8 */5 * *'   # cada 5 días a las 8am

jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - name: Ping Supabase
        run: |
          curl -X GET \
            'https://jqkyifuyaxxwugrnjfnq.supabase.co/rest/v1/perfiles?select=id&limit=1' \
            -H 'apikey: TU_ANON_KEY' \
            -H 'Authorization: Bearer TU_ANON_KEY'
Sin keep alive: Día 1 ── Día 7 ── PAUSA ── error ── reactivás manualmente Con keep alive: Día 1 ── Día 5 ── 🤖 ping automático ── Día 10 ── 🤖 ping ── nunca pausa
Costo del keep alive $0. GitHub Actions incluye 2.000 minutos gratuitos por mes. Este job tarda menos de 10 segundos cada 5 días.
