Pasos de implementación
1
Autenticación real en index.html
Reemplazar doLogin() por llamadas reales a Supabase Auth
La función doLogin() actual solo valida que los campos no estén vacíos. Hay que reemplazarla por las tres funciones principales de Supabase Auth:
// LOGIN
const { data, error } = await sb.auth.signInWithPassword({
  email: 'usuario@email.com',
  password: 'contraseña'
})
if (!error) window.location.href = 'agrotrace_prototipo_v3.html'

// REGISTRO
const { data, error } = await sb.auth.signUp({
  email, password
})

// LOGOUT
await sb.auth.signOut()
window.location.href = 'index.html'
Nota: Supabase envía un email de confirmación al registrarse. Esto puede desactivarse en el dashboard de Supabase → Authentication → Settings → "Enable email confirmations".
2
Leer perfil y rol al iniciar la app
Reemplazar el auto-login hardcodeado por lectura de sesión activa
Al cargar el v3, en lugar del auto-login con DEV_EMAIL/DEV_PASSWORD, verificar si hay una sesión activa y leer el perfil del usuario:
async function iniciarApp() {
  // Verificar si hay sesión activa
  const { data: { user } } = await sb.auth.getUser()
  if (!user) {
    window.location.href = 'index.html' // sin sesión → login
    return
  }

  // Leer perfil y rol desde la tabla perfiles
  const { data: perfil } = await sb
    .from('perfiles')
    .select('*')
    .eq('id', user.id)
    .single()

  // Guardar globalmente
  CURRENT_USER = user
  CURRENT_ROL  = perfil.rol  // 'operador', 'administrador', etc.
  CURRENT_NOMBRE = perfil.nombre

  // Continuar cargando la app
  await Promise.all([cargarLotes(), cargarMaterial()])
}
Importante: Si no hay sesión activa, redirigir al login inmediatamente. Nunca mostrar datos sin usuario autenticado.
3
Adaptar la interfaz según el rol
Mostrar u ocultar funciones según CURRENT_ROL
Con CURRENT_ROL disponible, la interfaz puede mostrar u ocultar elementos según el nivel del usuario:
function aplicarPermisosPorRol() {
  const esAdmin = CURRENT_ROL === 'administrador'
  const esRT    = CURRENT_ROL === 'responsable_tecnico'
  const esInsp  = CURRENT_ROL === 'inspector'

  // Mostrar panel de gestión de usuarios solo a admin
  mostrarSi('nav-usuarios', esAdmin || esRT)

  // Ocultar botones de edición al inspector
  if (esInsp) {
    document.querySelectorAll('.btn-primary, .btn-advance')
      .forEach(b => b.style.display = 'none')
  }
}
Nota: La RLS en Supabase ya protege los datos a nivel de base de datos. Esta capa de interfaz es adicional para mejorar la experiencia del usuario — no reemplaza la seguridad del backend.
4
Crear usuarios con su perfil
Alta de nuevos usuarios con rol asignado por el administrador
Al registrar un usuario nuevo, además del signUp en Supabase Auth hay que insertar su fila en la tabla perfiles con el rol correspondiente:
async function crearUsuario(nombre, email, password, rol) {
  // 1. Crear en Supabase Auth
  const { data, error } = await sb.auth.signUp({ email, password })
  if (error) { alert(error.message); return }

  // 2. Insertar perfil con rol asignado
  await sb.from('perfiles').insert({
    id:     data.user.id,
    nombre: nombre,
    rol:    rol    // 'operador', 'inspector', 'administrador', etc.
  })
}
Nota: Solo el Super Administrador o el RT (según corresponda) pueden ejecutar esta función. El rol asignado determina todo lo que el usuario podrá ver y hacer en el sistema.

Qué hay implementado actualmente y cómo
ElementoQué esCómo está implementado hoy
index.html — formulario de login Pantalla de bienvenida con campos email y contraseña. El formulario existe visualmente. La función doLogin() solo verifica que los campos no estén vacíos — no conecta con ninguna base de datos. Es pura interfaz sin backend real.
Supabase Auth configurado Módulo de autenticación activo en el proyecto Supabase. En el dashboard de Supabase → Authentication el módulo está activo. Ya existe un usuario de prueba creado manualmente desde ese dashboard para poder probar el sistema.
SDK de Supabase cargado Librería JavaScript que permite al HTML hablar con Supabase. Se carga desde CDN en el <head> del v3. Luego se inicializa el cliente sb con la URL y la anon key del proyecto. Sin esto ninguna consulta funcionaría.
Tabla perfiles con campo rol Tabla que extiende auth.users con datos adicionales del usuario. Creada en el schema original. Tiene columna rol con valores posibles: productor, inspector, operador, administrador. Vinculada a Supabase Auth. Actualmente vacía salvo carga manual.
RLS activo en todas las tablas Mecanismo de PostgreSQL que filtra qué filas puede ver cada usuario. Habilitado en cada tabla del schema. Las políticas filtra por auth.uid() = usuario_id. Funciona automáticamente porque el cliente sb envía el token del usuario en cada consulta.
Auto-login provisorio Login automático sin pantalla, usando credenciales fijas en el código. Al cargar el v3, el sistema ejecuta sb.auth.signInWithPassword() con DEV_EMAIL y DEV_PASSWORD hardcodeados. Es un atajo para pruebas — no apto para producción porque las credenciales son visibles en el código fuente.
Glosario de siglas y términos técnicos
Sigla / TérminoExpansiónQué significa en la práctica
IAM Identity and Access Management Sistema completo que gestiona quién puede acceder a una plataforma y qué puede hacer dentro de ella. Engloba autenticación, autorización y gestión de usuarios.
AuthN Authentication (Autenticación) Proceso de verificar la identidad de un usuario. Responde a: ¿quién sos? Se implementa con email + contraseña, biometría, tokens, etc.
AuthZ Authorization (Autorización) Proceso de verificar qué puede hacer un usuario ya identificado. Responde a: ¿qué tenés permitido hacer? Se implementa con roles y permisos.
RBAC Role-Based Access Control Modelo de autorización donde los permisos se agrupan en roles (Operador, Inspector, etc.) y los roles se asignan a usuarios. Es el modelo que usa AgroTrace.
RLS Row Level Security Mecanismo de PostgreSQL que filtra automáticamente qué filas de una tabla puede ver o modificar cada usuario, según políticas definidas en SQL.
JWT JSON Web Token Token firmado digitalmente que Supabase entrega al usuario al hacer login. Contiene su identidad y expira automáticamente. Se envía en cada consulta para autenticar la sesión.
SDK Software Development Kit Librería de código provista por Supabase que simplifica la conexión desde JavaScript. En AgroTrace se carga desde CDN y se usa como el objeto sb.
CDN Content Delivery Network Red de servidores distribuidos que sirve archivos estáticos (como el SDK de Supabase) desde el servidor más cercano al usuario, de forma rápida y sin instalación.
API Application Programming Interface Interfaz que permite que dos sistemas se comuniquen. Supabase expone una API REST que el SDK usa internamente para leer y escribir en la base de datos.
REST Representational State Transfer Estilo de arquitectura para APIs web. Las operaciones se hacen con métodos HTTP estándar (GET, POST, PATCH, DELETE) sobre URLs que representan recursos.
SaaS Software as a Service Modelo de distribución donde el software se ofrece como servicio online, sin que el cliente instale nada. AgroTrace es una plataforma SaaS.
UUID Universally Unique Identifier Identificador único de 128 bits generado automáticamente. Supabase lo usa como clave primaria de todas las tablas (ej: id en lotes_produccion).
SQL Structured Query Language Lenguaje estándar para consultar y manipular bases de datos relacionales. Se usa en Supabase para crear tablas, definir políticas RLS y ejecutar migraciones.
SPA Single Page Application Aplicación web que carga una sola página HTML y cambia el contenido dinámicamente con JavaScript, sin recargar el navegador. AgroTrace v3 es una SPA.
ONG Organización No Gubernamental En el contexto de REPROCANN, las organizaciones habilitadas para el cultivo de cannabis medicinal. Son la unidad de tenant en la arquitectura multi-tenant de AgroTrace.
RT Responsable Técnico Figura profesional obligatoria en REPROCANN que supervisa y avala el proceso productivo de una ONG. En AgroTrace tiene Nivel 1 de acceso.
REPROCANN Registro del Programa de Cannabis Marco regulatorio argentino (ANMAT) que habilita el cultivo de cannabis medicinal a ONG y sus asociados. Define cupos, roles y obligaciones de trazabilidad.
BD / DB Base de Datos / Database Sistema de almacenamiento estructurado de información. AgroTrace usa PostgreSQL como base de datos relacional, gestionada a través de Supabase.
HTML HyperText Markup Language Lenguaje de marcado que define la estructura visual de una página web. Cada pantalla de AgroTrace es un archivo HTML con CSS y JavaScript embebidos.
CSS Cascading Style Sheets Lenguaje que define el estilo visual (colores, tipografías, espaciados). En AgroTrace está embebido dentro del <style> de cada HTML.
JS JavaScript Lenguaje de programación que corre en el navegador y da interactividad a la interfaz. Maneja la lógica de AgroTrace, las consultas a Supabase y la navegación entre vistas.
