1
¿Qué es un Backend?

Hoy el prototipo AgroTrace es 100% frontend: todo el código corre en el navegador del usuario. Si se recarga la página, los datos desaparecen. Si dos usuarios abren la misma URL, ven datos distintos. No existe "memoria" compartida.

El backend es un programa que corre en un servidor (una computadora que nunca se apaga, en un data center), y actúa como intermediario entre el usuario y la base de datos.

USUARIO (navegador) SERVIDOR (backend) BASE DE DATOS ────────────────── ────────────────── ───────────────── "Quiero mis lotes" → Recibe el pedido Verifica quién sos → SELECT * FROM lotes Recibe los datos ← WHERE productor_id = 42 "Acá están tus lotes" ← Formatea y responde
Regla fundamental
El usuario nunca habla directamente con la base de datos. El backend decide qué puede ver cada usuario, aplica las reglas de negocio y guarda todo de forma permanente.
2
Persistencia de datos entre sesiones
❌
Estado actual (prototipo)
Los datos son constantes JavaScript hardcodeadas en memoria RAM del navegador. Al recargar: todo desaparece. Sin historial, sin usuarios reales.
✅
Con backend + base de datos
Los datos se guardan en PostgreSQL. El lunes cargás un lote; el jueves desde otro celular, el lote sigue ahí, intacto.

Flujo de autenticación real:

  1. Usuario ingresa usuario + contraseña.
  2. El backend verifica contra la base de datos.
  3. Si es correcto, genera un token JWT — como una llave temporal, válida por X horas.
  4. El token se guarda en el navegador del usuario.
  5. Cada pedido incluye el token → el backend sabe quién es → devuelve solo sus datos.
Separación multi-productor
Cada productor tiene un productor_id único. La base de datos garantiza que un productor nunca puede ver los datos de otro, incluso si intenta manipular la URL.
3
Opciones de servidor gratuito

Para el volumen esperado de AgroTrace (decenas de productores, no millones), estas opciones gratuitas son más que suficientes:

Servicio Qué ofrece gratis Limitación Recomendado
Supabase PostgreSQL + Auth + API automática 500 MB DB, 50k usuarios ★ Primera opción
Railway Node.js / Python + PostgreSQL $5 crédito/mes Alternativa
Render Node.js / Python hosting Se "duerme" tras 15 min sin uso Con caveats
Vercel Serverless functions (Node.js) Sin base de datos incluida Parcial
Neon PostgreSQL serverless 0.5 GB Solo DB
¿Por qué Supabase para AgroTrace?
  • El ERD ya es PostgreSQL → migración directa sin conversión.
  • Incluye autenticación con roles lista para usar.
  • Tiene Row Level Security (RLS): la regla "cada productor ve solo sus lotes" se aplica en la base de datos misma, no solo en el código.
  • Genera una API REST automáticamente desde tus tablas.
  • Dashboard excelente para ver y editar datos como administrador.
4
Proteger el código del sistema

La regla más importante para ofrecer el servicio con seguridad:

Lo que el usuario SÍ ve
✔ HTML — estructura visual
✔ CSS — estilos
✔ JS — comportamiento de botones

Esto es normal. El frontend no tiene secretos: solo tiene formularios.
Lo que el usuario NUNCA ve
✘ Lógica de negocio (backend)
✘ Consultas a la base de datos
✘ Reglas de descuento de stock
✘ Validaciones REPROCANN
✘ Credenciales / contraseñas
┌─────────────────────────────┐ │ Tu servidor (PRIVADO) │ │ ───────────────────────── │ │ Código backend │ Productores ──► │ Reglas REPROCANN │ (ven solo su │ Descuento de stock │ interfaz) │ Validaciones de lotes │ │ Separación por productor │ Admin ──► │ │ (ve todo) └──────────────┬──────────────┘ │ ┌──────────────▼──────────────┐ │ PostgreSQL (PRIVADO) │ │ Datos separados por │ │ productor_id │ └─────────────────────────────┘
Medidas concretas de protección
  • Repositorio privado en GitHub: nadie puede ver el código fuente.
  • Variables de entorno: las contraseñas de la DB nunca van en el código.
  • El cliente recibe solo datos (JSON): nunca el código que los genera.
  • Minificación del frontend (opcional): Vite/esbuild comprimen y ofuscan el JS visible.
5
Camino de implementación para AgroTrace
✓
HECHO — Prototipo funcional
HTML estático, datos hardcodeados, UI completa de lotes y material básico.
1
Crear proyecto en Supabase
Migrar el ERD definitivo a tablas PostgreSQL reales. Configurar Row Level Security por productor_id.
2
Conectar autenticación
Reemplazar el doLogin() actual por Supabase Auth. Cada usuario tiene rol asignado (productor / inspector / admin).
3
Conectar el frontend via Supabase JS SDK
Las listas de lotes y material dejan de ser constantes fijas y se consultan en tiempo real desde la base de datos.
4
Desplegar frontend en Vercel o Netlify
URL pública gratuita (ej: agrotrace.vercel.app). Productores acceden con su usuario/contraseña y ven solo sus datos.
5
Migrar a React + Vite (futuro)
Cuando el prototipo esté validado, refactorizar a componentes React para escalabilidad y mantenibilidad a largo plazo.
Resultado final
agrotrace.com.ar → Productores inician sesión → Ven solo sus datos → Vos como admin ves todo → El código permanece privado en GitHub → Sin costo mensual en las etapas iniciales.
