¿Alcanza con VS Code?
La respuesta corta: sí, completamente
💻

VS Code es suficiente para todo el camino

Para los pasos 1 al 4 no necesitás ninguna otra herramienta. Ya lo estás usando bien. VS Code tiene terminal integrada — todo se hace desde ahí. No hay que instalar un IDE diferente ni aprender otra interfaz.

Lo único que sí hay que instalar (una sola vez)
⚙️
Node.js — nodejs.org
Se descarga e instala como cualquier programa de Windows. Con esto tenés acceso a todo el ecosistema de desarrollo web moderno.
¿Qué hace Node.js exactamente?
Node.js permite ejecutar JavaScript fuera del navegador — en tu computadora o en un servidor. También instala npm, el gestor de paquetes que te permite agregar librerías con un solo comando desde la terminal de VS Code.

Para arrancar el Paso 1 hoy
Tres acciones concretas, en orden
A
Crear cuenta en Supabase
Entrás a supabase.com, te registrás con tu cuenta de GitHub. Es gratis. Creás un nuevo proyecto con el nombre "agrotrace".
B
Migrar el ERD a tablas
Supabase tiene un editor SQL visual. Con el ERD que ya tenemos diseñado, se genera el script SQL exacto para crear todas las tablas. Lo pegás, lo ejecutás, y las tablas están listas.
C
Instalar Node.js
Descargás e instalás desde nodejs.org. Abrís la terminal de VS Code y escribís node --version — si te responde un número, está listo.
Importante recordar
No necesitás entender todo antes de empezar. El modelo de trabajo es: se genera el código → vos lo pegás y probás → preguntás qué hace cada parte → aprendés en el proceso. Así funciona el desarrollo asistido.

Reglas de negocio — Material Básico en Nursery
Qué descuenta stock, qué no, y por qué — crítico para implementar el wizard

Al confirmar un nuevo lote en Nursery, el sistema debe tratar el stock de origen de manera distinta según el tipo de material. Esta distinción refleja la biología del cultivo y es una regla de negocio no negociable.

Tipo de origen ¿Descuenta stock? Campo afectado Razonamiento
Semillas ✓ Sí lotes_semillas.
stock_actual		 La semilla se consume físicamente al germinar. Cada semilla usada es una semilla menos en stock.
Esquejes externos ✓ Sí lotes_esquejes.
stock_actual		 El esqueje comprado es una unidad consumible. Al plantarlo en Nursery deja de estar disponible como stock.
Plantas Madre ✗ No lotes_plantas_madre.
esquejes_extraidos (solo informativo)		 La planta madre no se consume: sigue existiendo y puede dar más esquejes. El stock refleja cuántas plantas hay, no cuántos esquejes pueden dar. No es posible predecir su capacidad de entrega.
Restricción adicional — Origen de Esquejes
Un lote de Esquejes externos no puede tener como origen un lote de Semillas propio. Solo puede originarse en compra externa o en Plantas Madre propias. Esta restricción debe validarse al crear un lote de esquejes.
Impacto en el wizard de Nuevo Lote
  • Semillas: el wizard muestra un campo de cantidad separado en el paso Origen (puede ser en gramos, sobres o unidades — distinto a las plántulas de Nursery). El descuento se calcula sobre ese campo.
  • Esquejes: no hay campo de cantidad separado en Origen — la cantidad que va a Nursery es la que se descuenta del stock. Se captura una sola vez en el paso Nursery.
  • Plantas Madre: no hay campo de cantidad en Origen ni descuento. Solo se registra el vínculo (origen_pm_id) y se incrementa esquejes_extraidos como dato informativo.

Resumen ejecutivo

  • VS Code es suficiente para todo el camino — no cambies de herramienta.
  • Solo necesitás instalar Node.js (una vez, gratis).
  • Los pasos más fáciles son Supabase (1) y Deploy en Vercel (4) — casi sin código.
  • El paso más técnico es conectar el frontend (3) — se trabaja línea por línea.
  • React (paso 5) no es urgente — el sistema puede funcionar perfecto en HTML puro.
  • El MVP demostrable a clientes requiere solo los pasos 1 → 2 → 3 → 4.
