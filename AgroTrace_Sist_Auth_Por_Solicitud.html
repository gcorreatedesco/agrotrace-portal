Guía de Procedimiento

Sistema de Autenticación
por Solicitud

Diseño y procedimiento del flujo de registro de nuevos usuarios en AgroTrace: el usuario solicita acceso, el administrador aprueba, y el sistema envía las credenciales automáticamente.

Documento: AgroTrace_Sist_Auth_Por_Solicitud
Versión: v1.1
Fecha: Junio 2026

1. Concepto

En lugar de que los usuarios se registren libremente, AgroTrace implementa un sistema de acceso por aprobación. El usuario completa un formulario de solicitud, el administrador lo revisa y aprueba, y recién ahí el sistema le envía el link para crear su contraseña.

Este modelo es adecuado para AgroTrace porque:

  • El acceso al sistema está vinculado a un vínculo regulatorio real (REPROCANN)
  • No cualquier persona puede ser productor — debe estar validada por un RT
  • Previene registros fraudulentos o erróneos desde el inicio
El usuario nunca elige su contraseña inicial El administrador no le "manda una contraseña" — Supabase genera un link de activación seguro y el usuario define su propia contraseña al hacer clic. El administrador nunca conoce la contraseña del usuario.

3. Las dos opciones de implementación

Aprobación desde Supabase Dashboard

  • Sin desarrollo adicional en el sistema
  • Funciona desde el día uno
  • Ideal para pocas ONGs (menos de 10)
  • El administrador tiene control total

5. Procedimiento detallado — Opción A

Dashboard de Supabase como herramienta de aprobación

  • 1
    Usuario completa el formulario de solicitud
    Desde index.html → opción "Solicitar acceso". El sistema envía un email al administrador con todos los datos del formulario usando un servicio como EmailJS (no requiere backend) o directamente con Supabase Edge Functions.
  • 2
    El administrador recibe el email de notificación
    El email incluye: nombre, organización, email, perfil solicitado y número REPROCANN. El administrador evalúa si la solicitud es legítima y corresponde al marco REPROCANN.
  • 3
    Crear el usuario en Supabase Dashboard
    Ir a: Supabase Dashboard → Authentication → Users → Add user
    Completar:
    Email: email del solicitante Password: (cualquier valor — el usuario lo cambiará) Activar: "Send email confirmation"
    Supabase envía automáticamente el link de activación al email del usuario.
  • 4
    Asignar el rol en la tabla perfiles
    En Supabase → Table Editor → perfiles → Insert row:
    id: [UUID del usuario recién creado — se ve en Authentication → Users] nombre: [nombre del solicitante] rol: 'ong' o 'rt'
  • 5
    El usuario activa su cuenta
    El usuario recibe el email de Supabase con el link. Al hacer clic, es redirigido a AgroTrace donde define su contraseña. Su cuenta queda activa con el rol asignado. Puede ingresar desde index.html normalmente.
  • 6
    Notificar al usuario que su acceso fue aprobado (opcional)
    El email de activación de Supabase ya funciona como notificación. Opcionalmente, el administrador puede enviar un email adicional de bienvenida con instrucciones de uso.

6. Procedimiento detallado — Opción B

Panel de administración en la aplicación

Esta opción requiere desarrollo adicional Implica crear una tabla en Supabase, una pantalla dentro de la app y lógica de aprobación. Se recomienda implementar cuando el sistema tenga usuarios reales y la Opción A resulte insuficiente.

Componentes a desarrollar

Componente Descripción Dónde
Tabla solicitudes_acceso Almacena cada solicitud con estado: pendiente / aprobada / rechazada Supabase SQL
Formulario de solicitud Igual que Opción A — guarda en la tabla en lugar de enviar email index.html
Pantalla "Solicitudes" Lista de solicitudes pendientes con datos del solicitante. Visible solo para Superadmin y RT agrotrace_prototipo_v3.html
Botón "Aprobar" Ejecuta inviteUserByEmail() de Supabase, cambia estado a "aprobada" agrotrace_prototipo_v3.html
Botón "Rechazar" Cambia estado a "rechazada" y opcionalmente envía email al solicitante agrotrace_prototipo_v3.html

Esquema SQL de la tabla solicitudes_acceso

CREATE TABLE public.solicitudes_acceso ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), nombre TEXT NOT NULL, email TEXT NOT NULL, organizacion TEXT NOT NULL, rol_solicitado TEXT NOT NULL CHECK (rol IN ('rt', 'ong')), nro_reprocann TEXT, notas TEXT, estado TEXT NOT NULL DEFAULT 'pendiente' CHECK (estado IN ('pendiente','aprobada','rechazada')), aprobado_por UUID REFERENCES public.perfiles(id), creado_en TIMESTAMPTZ DEFAULT NOW(), resuelto_en TIMESTAMPTZ ); ALTER TABLE public.solicitudes_acceso ENABLE ROW LEVEL SECURITY;
  • 1
    Usuario completa el formulario de solicitud
    Los datos se guardan en solicitudes_acceso con estado pendiente. El administrador recibe un email de notificación automático (vía Supabase trigger o Edge Function).
  • 2
    Superadmin / RT ve las solicitudes en la app
    En el módulo "Gestión de usuarios" aparece un badge con el número de solicitudes pendientes. La pantalla muestra una card por solicitud con todos los datos del formulario.
  • 3
    Aprobar la solicitud
    Al hacer clic en "Aprobar", el sistema ejecuta:
    // 1. Invitar al usuario via Supabase Auth const { data, error } = await sb.auth.admin.inviteUserByEmail( solicitud.email, { data: { rol: solicitud.rol_solicitado } } ); // 2. Marcar solicitud como aprobada await sb.from('solicitudes_acceso') .update({ estado: 'aprobada', resuelto_en: new Date() }) .eq('id', solicitud.id);
    Supabase envía automáticamente el email de invitación al usuario.
  • 4
    El usuario activa su cuenta
    Igual que Opción A — el usuario recibe el email, hace clic en el link y define su contraseña. Un trigger en Supabase crea automáticamente el registro en perfiles con el rol correcto.
  • 5
    Rechazar una solicitud
    Si la solicitud no corresponde, el administrador la rechaza con un motivo opcional. El sistema actualiza el estado y puede enviar un email automático informando al solicitante.

7. Trigger para creación automática de perfiles

Cuando Supabase crea un usuario nuevo (en ambas opciones), se puede configurar un trigger de PostgreSQL que inserta automáticamente el registro en la tabla perfiles, sin que el administrador tenga que hacerlo manualmente.

-- Función que se ejecuta al crear un nuevo usuario en auth.users CREATE OR REPLACE FUNCTION public.handle_new_user() RETURNS TRIGGER AS $$ BEGIN INSERT INTO public.perfiles (id, nombre, rol) VALUES ( NEW.id, COALESCE(NEW.raw_user_meta_data->>'nombre', NEW.email), COALESCE(NEW.raw_user_meta_data->>'rol', 'ong') ); RETURN NEW; END; $$ LANGUAGE plpgsql SECURITY DEFINER; -- Trigger que llama a la función al crear cada usuario CREATE OR REPLACE TRIGGER on_auth_user_created AFTER INSERT ON auth.users FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
Este trigger elimina el paso manual de la Opción A Con el trigger activo, al crear el usuario en Supabase Dashboard el perfil se crea solo. El administrador solo necesita ingresar el email — no tiene que insertar manualmente en la tabla perfiles.

10. Procedimiento de deploy de la Edge Function

La Edge Function es el componente que recibe los datos del formulario y envía el email al administrador. El código vive en supabase/functions/solicitar-acceso/index.ts dentro del repositorio. Para que funcione, debe estar desplegado en los servidores de Supabase.

Parte A — Crear cuenta en Resend y obtener API Key

  • 1
    Registrarse en Resend
    Ir a resend.com → Sign up. Plan gratuito: 3.000 emails/mes — más que suficiente para solicitudes de acceso.
  • 2
    Obtener API Key
    En el dashboard de Resend: API Keys → Create API Key. Copiar la clave generada (empieza con re_). Guardarla — solo se muestra una vez.

Parte B — Configurar Secrets en Supabase

Los secrets son variables de entorno seguras — nunca quedan visibles en el código del repositorio.

  • 3
    Ir a Secrets en Supabase
    Supabase Dashboard → Project Settings → Edge Functions → Secrets
  • 4
    Agregar los tres secrets
    Nombre del secret Valor
    RESEND_API_KEY La clave re_... obtenida en el paso 2
    ADMIN_EMAIL El email del administrador que recibirá las solicitudes
    FROM_EMAIL AgroTrace <onboarding@resend.dev> (hasta verificar dominio propio)

Parte C — Deploy de la Edge Function

  • 5
    Ir a Edge Functions en Supabase
    Supabase Dashboard → Edge Functions → Deploy a new function
  • 6
    Crear la función
    Nombre: solicitar-acceso (debe coincidir exactamente con este nombre).
    Abrir el archivo supabase/functions/solicitar-acceso/index.ts del repositorio, copiar todo el contenido y pegarlo en el editor de Supabase.
  • 7
    Guardar y verificar el deploy
    Hacer clic en Deploy. Supabase mostrará la URL de la función, similar a:
    https://jqkyifuyaxxwugrnjfnq.supabase.co/functions/v1/solicitar-acceso
    Esa URL ya está configurada en index.html — no hay nada más que cambiar en el código.

Parte D — Personalizar el template de invitación

  • 8
    Ir a Email Templates en Supabase
    Supabase Dashboard → Authentication → Email Templates → Invite user
  • 9
    Reemplazar el contenido por el template en español
    <h2>Bienvenido a AgroTrace</h2> <p>Su solicitud de acceso fue aprobada.</p> <p>Haga clic en el siguiente enlace para crear su contraseña y activar su cuenta:</p> <a href="{{ .ConfirmationURL }}">Activar mi cuenta</a> <p>Este enlace expira en 24 horas.</p> <p>Si no solicitó acceso a AgroTrace, ignore este email.</p>

Parte E — Trigger para creación automática de perfiles

  • 10
    Ejecutar en Supabase SQL Editor
    Supabase Dashboard → SQL Editor → New query — pegar y ejecutar:
    CREATE OR REPLACE FUNCTION public.handle_new_user() RETURNS TRIGGER AS $$ BEGIN INSERT INTO public.perfiles (id, nombre, rol) VALUES ( NEW.id, COALESCE(NEW.raw_user_meta_data->>'nombre', NEW.email), COALESCE(NEW.raw_user_meta_data->>'rol', 'ong') ); RETURN NEW; END; $$ LANGUAGE plpgsql SECURITY DEFINER; CREATE OR REPLACE TRIGGER on_auth_user_created AFTER INSERT ON auth.users FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
    Con este trigger activo, al crear un usuario en Supabase el perfil se genera automáticamente — sin inserción manual.

6. Creación directa de usuarios — Edge Functions `crear-rt` y `crear-ong`

Alternativamente al flujo por solicitud, el Superadmin puede crear usuarios RT y ONG directamente desde el portal sin que ellos reciban emails de invitación. El Superadmin proporciona email + contraseña.

Flujo de creación directa:

1. Superadmin crea un RT:

Entrada del portal
Email: juan@example.com Contraseña: MiPass123 Nombre: Juan Pérez ↓ (Click "Crear RT") ↓ Edge Function crear-rt.ts se ejecuta ↓ Crea usuario en Supabase Auth con metadatos: rol='rt', nombre_contacto ↓ Trigger on_auth_user_created se dispara automáticamente ↓ Crea perfil en tabla perfiles (id, nombre, rol='rt') ↓ ✅ RT listo para loguearse con email + contraseña

2. Superadmin crea una ONG:

Entrada del portal
Nombre ONG: Asociación Esperanza Verde Email Admin: maria@ong.org Contraseña: OngPass456 Nombre Admin: María López CUIT: 20-12345678-9 Localidad: Buenos Aires Nro. REPROCANN: REP-001 RT asignado: Juan Pérez (opcional) ↓ (Click "Crear ONG") ↓ Edge Function crear-ong.ts se ejecuta ↓ 1. Crea organización en tabla organizaciones 2. Si RT fue asignado, vincula en rt_organizaciones 3. Crea usuario en Auth con metadatos: rol='ong', ong_id ↓ Trigger on_auth_user_created se dispara ↓ Crea perfil en tabla perfiles (id, nombre, rol='ong', ong_id) ↓ ✅ ONG lista para loguearse ✅ El RT asignado ahora supervisa esta ONG

Edge Functions código:

crear-rt.ts — Ubicación: supabase/functions/crear-rt/index.ts

Responsabilidades
1. Verifica que el llamante es superadmin 2. Recibe: email, password, nombre 3. Crea usuario en Supabase Auth con user_metadata: { rol: 'rt', nombre_contacto } 4. Retorna: user_id, email, mensaje de éxito 5. El trigger automáticamente crea el perfil

crear-ong.ts — Ubicación: supabase/functions/crear-ong/index.ts

Responsabilidades
1. Verifica que el llamante es superadmin 2. Recibe: nombre_org, email_admin, password_admin, nombre_admin, [cuit, localidad, reprocann, rt_id] 3. Crea organización en tabla organizaciones 4. Si rt_id: vincula ONG al RT en rt_organizaciones 5. Crea usuario en Auth con user_metadata: { rol: 'ong', ong_id, nombre_contacto } 6. Retorna: org_id, user_id, mensaje 7. El trigger automáticamente crea el perfil vinculado a la ONG

Deployment en Supabase:

Comandos a ejecutar en Terminal
supabase functions deploy crear-rt supabase functions deploy crear-ong

Después del deploy, las Edge Functions están disponibles en:

Endpoints
POST https://jqkyifuyaxxwugrnjfnq.supabase.co/functions/v1/crear-rt POST https://jqkyifuyaxxwugrnjfnq.supabase.co/functions/v1/crear-ong

Ventajas del flujo directo:

  • ✓ Automatizado: Superadmin no necesita ir a Supabase Dashboard
  • ✓ Escalable: Crea 1000 usuarios sin fricción
  • ✓ Sin emails: El usuario no recibe link de invitación, solo sus credenciales
  • ✓ Auditoría: Logs en Supabase Edge Functions de quién creó qué
  • ✓ Control de contraseña: El Superadmin define la contraseña inicial (puede requerir cambio al primer login)
Recomendación de flujo actual Usar Edge Functions crear-rt y crear-ong. Estas son operaciones internas (solo Superadmin) y no requieren aprobación externa. El flujo por solicitud + panel de aprobación es innecesario en esta fase.
Flujo completo de creación de usuarios Superadmin completa formulario en portal → Llama Edge Function → Edge Function crea usuario en Supabase Auth → Trigger on_auth_user_created se dispara automáticamente → Perfil se crea en tabla perfiles → Usuario puede loguearse inmediatamente con email + contraseña.
